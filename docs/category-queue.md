# カテゴリキュー処理（w-ja-nn5）

`src/category-queue.js` は、[プロジェクト:カテゴリ関連/キュー](https://ja.wikipedia.org/wiki/プロジェクト:カテゴリ関連/キュー) に提出されたコマンドを読み、カテゴリの再配属・除去を行い、結果を同じ節に `{{BOTREQ}}` 付きで返信します。

- **背景:** QueueBot による自動処理は約1年停止しています。「Wikipedia‐ノート:Bot作業依頼」で、単純なカテゴリ付け替えに限り、種別C の Bot による手動でのキュー再開が提案されました（2026年10月8日）。
- **運用:** 当面は運用者が手動で起動します。`tasks.json` にジョブは登録していません。
- **参考実装:** 構文と編集要約は QueueBot（[mirror-kt/wikimedia-jp-queue-bot](https://github.com/mirror-kt/wikimedia-jp-queue-bot)）に合わせています。

| 部品 | 役割 |
| --- | --- |
| `src/category-queue.js` | 本体。引数、Wiki への問い合わせ、対象収集、編集、返信、記録、取り消し |
| `utils/categoryQueue/queue.js` | 節の分割、見出しの解釈、議論リンク、処理済み判定、返信の挿入 |
| `utils/categoryQueue/replacer.js` | 本文の書き換え（5章） |
| `utils/categoryQueue/report.js` | 編集要約と返信文（6章） |
| `utils/categoryQueue/requester.js` | 依頼者・依頼日時の特定と署名の照合（2.5） |
| `utils/categoryQueue/record.js` | コマンドごとの記録（Web の詳細ページ。8章） |
| `utils/categoryQueue/status.js` | 実行状況の書き出しと二重起動の防止（9章） |
| `utils/categoryQueue/title.js` | カテゴリ名の正規化 |
| `utils/parse2.js` | 見出し・リンク・テンプレート・カテゴリの解析（[parser.md](parser.md)） |

## 1. 用語

| 用語 | 意味 |
| --- | --- |
| キューページ | プロジェクト:カテゴリ関連/キュー |
| 節 | キューページの第2レベル見出し（`== … ==`）1つ分 |
| コマンド | 見出しから解釈した操作（再配属・除去） |
| 移動元 / 移動先 | 操作前のカテゴリ（A）/ 操作後のカテゴリ（B…） |
| ID | 処理した節ごとに振る識別子（例: `20261013061530-a1b2c3`）。不受理・不可能にも振る。編集要約・返信・Web の詳細ページ・取り消しで使う |
| 依頼者 | キューページの履歴で、その見出しを書き込んだ利用者（2.5）。署名の利用者とは限らない |

## 2. キュー構文

第2レベル見出しが `Bot:` で始まる節だけをコマンドとして扱います（`queue.parseCommandHeading`）。

| 見出し | 種別 | 対象名前空間 |
| --- | --- | --- |
| `Bot: [[:Category:A]]を[[:Category:B]]へ` | 再配属（reassign） | 標準(0)・Category(14) |
| `Bot: (記事) [[:Category:A]]を[[:Category:B]]へ` | 再配属 | 標準のみ |
| `Bot: (カテゴリ) [[:Category:A]]を[[:Category:B]]へ` | 再配属 | Category のみ |
| `Bot: [[:Category:A]]を除去` | 除去（remove） | 標準・Category |

- `(記事)` `(カテゴリ)` は除去にも付けられます。
- 移動先は1つだけです。複数の移動先（`[[:Category:A]]を[[:Category:B]]と[[:Category:C]]へ`）と複製（`[[:Category:A]]を[[:Category:B]]に複製`）は受け付けません（不受理）。
- 移動元が「…の画像提供依頼」で範囲指定が無いときは、ノート(1)も対象に加えます（`{{画像提供依頼}}` はノートに貼られるため）。

### 2.1 表記の許容範囲

- `&nbsp;` `&#160;` ノーブレークスペースは空白として扱う（導入文の申請例が `Bot:&nbsp;` のため）
- `Bot` の大文字小文字、全角の「：」「（記事）」を許す
- リンクと「を」「と」「へ」の間の空白を許す
- リンクの名前空間は `Category:` `category:` `カテゴリ:`。パイプ付き `[[:Category:B|表示名]]` も可
- カテゴリ名は `_` と空白を同一視し、連続空白をまとめ、先頭文字を大文字にして比べる

### 2.2 不受理にする条件

次のどれかに当たる節は実行せず、`{{BOTREQ|不受理}}` と理由を返信します。

1. コロンなしの `[[Category:A]]`（見出しに書くとキューページ自体が分類されるため、書き直しを求める）
2. 「を」、末尾の「へ」「を除去」のいずれかが無い
3. コマンドの後ろに余分な文字列がある
4. 移動先が2つ以上（「…と…へ」）、複製（「…に複製」）、移動元と移動先が同じ
5. 本文に議論場所へのリンクが無い（2.3）

### 2.3 議論場所のリンク

本文の内部リンクのうち最初のものを議論場所とします（導入文「申請文で示される最初のリンクから編集の要約テキストを生成する」）。ただし次は飛ばします。

- `[[:Category:…]]` などカテゴリ・ファイルへのリンク
- 利用者ページ・利用者‐会話ページ（署名）、特別ページ

コメントや `<nowiki>` の中のリンクは数えません。第3レベル以下の小見出しも本文に含めます。

### 2.4 実行しない節

- **見出しが `Bot:` で始まらない:** 異議がある場合は「Bot:」を外す、という導入文の運用に対応します。
- **本文に `{{BOTREQ}}`（引数を問わない）がある:** Bot 自身の返信に加え、人の作業者が `{{BOTREQ|着手}}` などを付けた節も二重に実行しません。再実行は新しい節で提出し直します。ただし、この Bot の着手の印（`{{BOTREQ|着手}} (ID: …)`）だけがある節は、再開・返信の再送の対象です（2.8）。
- **コメントアウトされた見出し:** 節として数えません。

### 2.5 依頼者と依頼日時

署名はただの文字列なので、他人の名前でも書けます。そこで、署名とは別にキューページの版の履歴から依頼者を特定します（`requester.js`）。

1. キューページの版を新しい順に取得し（50版ずつ、最大500版）、その節（見出し行と依頼文の両方が同じもの）を含む版を古い方へたどります。他の節の追加・過去ログ化には影響されません。
2. 節を含まない版の1つ後の版が「節を書き込んだ版」です。その版の利用者を **依頼者**、時刻を **依頼日時** とします。ページの最初の版まで含んでいれば、最初の版を書き込んだ版とします。
3. 本文で最初の利用者ページへのリンク（利用者‐会話は除く）を **署名の利用者** とし、依頼者と比べます。

| 結果 | 扱い |
| --- | --- |
| 一致 | そのまま実行する |
| 不一致（署名の偽装・代理での提出・見出しの書き換え） | 実行は続ける。実行ログに警告を残し、Web の詳細ページで「署名と不一致」を表示する |
| 特定できない（500版より古い、版が削除されている、利用者名が隠されている） | 実行は続ける。実行ログに警告を残す |

見出しが後から他の人に書き換えられた場合は、書き換えた人が依頼者になります。実行されるのは書き換え後の見出しなので、責任の所在としてはそれが正しいためです。

依頼者の資格は今のところ確かめていません（誰でも提出できる）。そのため、署名を偽装しても得られる権限は無く、不一致は記録と表示だけにしています。資格の条件を設けるときは、署名ではなくこの依頼者で判定します（11章の未決事項）。

### 2.6 節の追跡（着手の印）

キューページは実行中も変わります（他の節の追加、過去ログ化、異議、他の作業者の対応）。そこで、編集を始める前に節へ着手の返信を付け、その中の ID で節を追跡します。

```text
:{{BOTREQ|着手}} (ID: 20261014000000-a1b2c3) 処理を始めました。進み具合は[https://nanonabot2-01.toolforge.org/queue/20261014000000-a1b2c3 処理状況]で確認できます。 --~~~~
```

1. **着手:** 見出しの解釈・議論リンク・移動先カテゴリの存在を確かめ、受け付けられると分かってから着手を返信します。最新版で節を探し、まだ誰も `{{BOTREQ}}` を付けていないことを確かめて、同じ編集で書き込みます（間にキューページが変われば編集競合になり、最新版でやり直す）。このときだけ、見出し行と依頼文（本文の最初の行）の両方が同じ節を同じものとみなします（`queue.findByRequest`）。見つからない・2つ以上ある場合は見送ります。
2. **着手の後:** 節は印「`{{BOTREQ|着手}} (ID: …)`」の文字列で探します（`queue.findById`）。他の節の追加・過去ログ化や見出しの書き換えがあっても、その節だけが見つかります。
3. **不受理・不可能:** 着手せずに結果だけを返信します。このときも 1. と同じ方法で節を探します。

着手の返信には次の利点もあります。

- 処理中であることが他の作業者に見え、二重に作業されない
- Bot の署名が付くので、過去ログ化までの期間が延びる
- 緊急停止・異常終了しても、次の実行で印を見つけて同じ ID で再開できる（2.8）

返信しない実行（`--dry-run`・`--no-report`・`--max-pages`）では着手の返信をしません。

### 2.7 編集中の確認

編集中は2分ごと（環境変数 `CATEGORY_QUEUE_CHECK_MS` で変えられる）にキューページを読み、ID で節を確かめます。

| 結果 | 扱い |
| --- | --- |
| 変わっていない | 続ける |
| 見出しが変わった（「Bot:」を外す異議を含む） | 中止し、その節に「中止」を返信する（それまでに編集した件数も書く） |
| 他の作業者が `{{BOTREQ}}` を付けた | 中止し、その節に返信する |
| 見つからない（過去ログ化・除去） | 依頼は有効なので最後まで続ける。返信は投稿できないので記録し、Web に返信文を表示する |

### 2.8 再開と返信の再送

実行のたびにキューページから処理する節を選びます（`selectWork`）。

| 節の状態 | 扱い |
| --- | --- |
| `{{BOTREQ}}` が無い | 新しく実行する |
| この Bot の着手の印だけがあり、手元の記録（`commands/<ID>.json`）が終わっていない（緊急停止・異常終了） | 同じ ID の記録を開いて再開する。件数はページの結果（`commands/<ID>.pages.jsonl`）から数え直して積み増す。処理済みのページは移動元から外れているので、残りだけが対象になる。ただし中断している間に見出しが変わっていたら、別の操作を同じ ID で実行しないよう、何もせず「中止」を返信する |
| 着手の印があり、記録は終わっているが返信を投稿できていない | 記録に残した返信文を再送する |
| 他の作業者の `{{BOTREQ}}` がある、または手元に記録の無い印（手書きの印など） | 何もしない |

印が本当にこの Bot のものかは、手元に同じ ID の記録があるかで判断します。印を手で書いても、再開されることはありません。印は parse2 で `{{BOTREQ|着手}}` のテンプレートとその直後の「 (ID: …)」を読み取るので、コメントや `<nowiki>` の中に写された印は数えません。

## 3. 実行フロー

1回の起動で、未処理の節をページの上から順に1つずつ実行します。節ごとの問題は返信して次の節へ進み、緊急停止だけはその場で全体を止めます。

```text
起動 ─ 稼働スイッチ・緊急停止を確認 ─(停止)→ 終了
  │
  ├─ 未処理の「Bot:」節を順に取り出す ←───────────────┐
  │    ├─ 見出しを解釈・議論リンクを探す ─(失敗)→ 不受理を返信 ─┤
  │    ├─ 移動先の存在・対象ページを確認 ─(なし)→ 不可能を返信 ─┤
  │    ├─ 1ページずつ書き換えて保存・記録 ─(緊急停止)→ 中断（返信せず次回へ）
  │    └─ 完了を返信 ───────────────────────────┘
  └─ 終了
```

1. 引数を解釈する（10章）。不正なら終了
2. `--dry-run` でなければメタの稼働スイッチを確認する
3. 実行中の印（`run.lock`）を取る。他の実行が動いていれば終了
4. ログインし、利用者名を取得する（`{{bots}}` の判定に使う）
5. `--dry-run` でなければ緊急停止ページを確認する
6. `--rollback` 指定なら取り消し（8.1）をして終了
7. キューページの最新版を読み、未処理の節を取り出す（`--only` で絞り込み）
8. 処理する節を選ぶ（新規・再開・返信の再送。2.8）
9. 節ごとに:
    1. ID を振り、コマンドの記録（8章）を作る（再開なら同じ ID の記録を開く）
    2. 見出しを解釈し、議論リンクを探す。できなければ「不受理」
    3. 移動先カテゴリがすべて存在するか確かめる。無ければ「不可能」
    4. 着手を返信する（2.6）。節が変わっていたら見送る
    5. 履歴から依頼者と依頼日時を特定する（2.5）
    6. 対象ページを集める（4章）。無ければ「不可能」
    7. ページごとに: 緊急停止を確認 → （2分ごとに）ID で節を確認（2.7）→ 最新版を取得 → `{{bots}}` を確認 → 書き換え（5章）→ 変更があれば保存して記録
    8. 緊急停止なら返信せずに実行全体を終える（次の実行で同じ ID で再開する）
    9. 再配属なら移動元の残り件数を調べ、結果を返信する（6章）。返信できなければ返信文と理由を記録する（次の実行で再送する）
10. 予期しない例外は「中止」を返信し、運用者にメールで通知して次の節へ進む

## 4. 対象ページの収集

| 取得元 | API | 条件 |
| --- | --- | --- |
| カテゴリのメンバー | `list=categorymembers`、`cmtitle=Category:A`、続きもすべて | `cmnamespace` = 対象名前空間 |
| リダイレクトの所属カテゴリ | `list=search`、`insource:"A" hastemplate:"リダイレクトの所属カテゴリ"` | 対象に標準名前空間を含むときだけ。検索は標準名前空間のみ |

- 重複を除き、取得した順に処理します。
- テンプレート経由で所属しているページもメンバーとして取れます。本文に直接の指定が無ければ「変更なし」になり、返信で要確認として挙げます。
- 検索は全文検索の索引に依存するため、直前の編集が反映されていないことがあります。書き換えるかどうかは取得した最新版の本文で判断します。
- 移動先カテゴリが1つでも存在しなければ、収集の前に「不可能」を返します。
- 収集結果が0件なら「カテゴリに操作対象となる所属記事または所属カテゴリがありませんでした」と「不可能」を返します。

## 5. 本文の書き換え規則

`applyCategoryCommand(wikitext, command)` は、カテゴリタグ → `{{リダイレクトの所属カテゴリ}}` → `{{画像提供依頼}}` などの順に同じ操作を適用します。構文の解析には parse2 を使い、段階ごとに解析し直します。どれも変えなければ「変更なし」で保存しません。

### 5.1 共通規則

- **保護領域:** コメントと `<nowiki>` `<pre>` `<math>` `<syntaxhighlight>` `<source>` `<score>` `<chem>` `<ce>` の中は書き換えません（parse2 がこれらを解析しないため）。
- **名前の一致:** `_` と空白、空白の数、先頭文字の大文字小文字を無視します。それ以外は完全一致です（`Name1` は `Name10` に一致しない）。
- **並びの付け替え（`transformList`）:** テンプレート引数の書き換えはこの結果を元に行います。

| 操作 | 例（A → B） | 結果 |
| --- | --- | --- |
| 再配属 | X, A, Y | X, B, Y（A の位置に移動先を入れる） |
| 再配属（移動先が既にある） | X, A, B | X, B（重複させない） |
| 除去 | A, Y, A | Y（A をすべて除く） |

### 5.2 カテゴリタグ

対象は parse2 がカテゴリとして返す `[[Category:A]]` `[[カテゴリ:A|ソートキー]]` です。`[[:Category:A]]`（リンク）は対象外です。

- **再配属:** 最初の A タグを、移動先のタグで置き換えます（移動先が本文にまだ無い場合）。ソートキーは空白だけのもの（`| `）も含めて引き継ぎます。
- **移動先がすべて既にある場合:** A タグを消すだけです。
- **2つ目以降の A タグ:** 消します。
- **除去:** A タグをすべて消します。
- **行の扱い:** タグだけの行を消すときは改行も消し、空行を残しません。他の文字と同じ行のタグはタグだけを消します。
- **テンプレート引数の中のタグ**（例: `{{Infobox|x=[[Category:A]]}}`）も同じように書き換えます。

### 5.3 {{リダイレクトの所属カテゴリ}}

引数は `redirect1`〜`redirect10`、各リダイレクトのカテゴリ `N-1`〜`N-20`、1件目の省略形である位置引数 `1`〜`20` です（テンプレート本体で確認済み）。値は `Category:` なしの素の名前ですが、付いていても一致とみなします。

- 引数をグループ（`N-*` ごと、位置引数は別グループ）に分け、番号順の値に `transformList` を適用します。
- 書き換えは順番ごとの値の入れ替えで行い、元の空白・改行の書式を保ちます。増えた分はグループ最後の引数と同じ書式で後ろに足し、減った分は末尾から消します。番号は 1 から詰め直します。
- 空の引数（`|1-3=`）はそのままにします。
- 1グループが20件を超える場合はそのグループを書き換えず、警告を出します。
- ある redirectN のカテゴリが0件になった場合は引数を消し、「redirectN にカテゴリが残っていません」と警告します。
- 呼び出し全体でカテゴリが0件になった場合は、呼び出しごと消します。

### 5.4 {{画像提供依頼}} など

対象は `{{画像提供依頼}}` `{{画像募集中}}` `{{画像改訂依頼}}` で、移動元が「X の画像提供依頼」の形のときだけ動きます。

- 引数 `cat` `cat2` `cat3`… の値 X に対して、接尾辞「の画像提供依頼」を外した名前で `transformList` を適用します。
- 「…の画像提供依頼」以外への再配属は引数で表せないため、テンプレートを書き換えず（移動先を落として除去にしない）、要確認として警告します。

### 5.5 書き換えないもの

- テンプレートが出力するカテゴリ（例: `[[Category:{{{1}}}]]`、条件付きカテゴリ）
- 本文中の `[[:Category:A]]` リンクや「Category:A」という文字列
- `{{DEFAULTSORT}}` などカテゴリ以外の記述

## 6. 返信と編集要約

### 6.1 対象ページの編集要約

| 種別 | 編集要約 |
| --- | --- |
| 再配属 | `Bot: [[:Category:A]]から[[:Category:B]],[[:Category:C]]へ変更 ([[議論リンク\|議論場所]]) (ID: …)` |
| 除去 | `Bot: [[:Category:A]]を除去 ([[議論リンク\|議論場所]]) (ID: …)` |

編集は細部編集・Bot 編集とし、ウォッチリストは変えません。

### 6.2 返信の状態

返信は1行だけにし、ページの一覧・理由・実行ログは nanonaBot2 Web の詳細ページ（`https://nanonabot2-01.toolforge.org/queue/<ID>`）に載せます。変更しなかったページやエラーが多くても、キューページが長くならないようにするためです。

| `{{BOTREQ}}` | 条件 | 本文 |
| --- | --- | --- |
| 着手 | 受け付けて、編集を始める（2.6） | 「処理を始めました」と処理状況へのリンク |
| 完了 | 対象ページを最後まで処理した | 件数（「12件を編集しました（変更なし3件・要確認1件・エラー1件）。」）。0件の内訳は書かない |
| 不受理 | 見出しを解釈できない、議論リンクが無い | 理由 |
| 不可能 | 移動先カテゴリが無い、対象ページが0件 | 理由 |
| 中止 | 編集中に見出しが変わった・他の作業者が対応した（2.7）、Bot の内部エラー | 理由（編集中の中止なら、それまでに編集した件数も） |

どの状態でも、ID と詳細ページへのリンクを付けます。再配属では移動元カテゴリの残り件数（`prop=categoryinfo`）も書きます。

着手の直前に節が変わっていて見送った場合は返信しません。緊急停止で途中終了した場合も結果は返信せず、次の実行で同じ ID のまま残りのページを処理してから返信します（2.8）。

### 6.3 返信の例

```text
:{{BOTREQ|完了}} (ID: 20261013061530-a1b2c3) 12件を編集しました（変更なし1件・エラー1件）。 [[:Category:Name1]]は空になりました。 詳細は[https://nanonabot2-01.toolforge.org/queue/20261013061530-a1b2c3 処理結果]を参照してください。 --~~~~
:{{BOTREQ|不受理}} (ID: 20261013061531-d4e5f6) 議論場所へのリンクがありません。申請文に議論場所へのリンクを記載してください。 詳細は[https://nanonabot2-01.toolforge.org/queue/20261013061531-d4e5f6 処理結果]を参照してください。 --~~~~
```

### 6.4 キューページへの書き込み方

- 最新版を取得し直し、着手済みなら ID で、そうでなければ見出し行と依頼文で節を探します（2.6）。
- 節末尾の空白を詰めて返信を置き、次の節との間に空行を1つ入れます。
- 節が見つからない・特定できない場合は書き込みません。返信文と理由をコマンドの記録（`reply`）に残し、Web の詳細ページに「未投稿」として返信文を表示します。節が残っていれば次の実行で自動的に再送します（2.8）。過去ログ化されていれば、運用者が必要に応じて過去ログに手で貼ります。
- 編集要約は `Bot: /* 見出し（リンク記法を外したもの） */ キューの処理結果` です。

## 7. 安全策

| 仕組み | 確認するもの | 確認の時点 | 満たさないとき |
| --- | --- | --- | --- |
| 稼働スイッチ | メタ `User:NanonaBot2/tasks/data` の `ALL` と `w-ja-nn5` が `1` | 起動時 | 終了 |
| 二重起動の防止 | `data/category-queue/run.lock`（中に持ち主の札 `owner`） | 起動時と、1ページ編集するごと | 起動時なら終了（30分更新の無い印は異常終了とみなして取り直す。取り直すときは印を自分だけの名前に rename してから札を確かめて消すので、同時に取り直そうとした別の実行の新しい印を消さない）。編集中に印を他の実行に取られていたら、それ以上編集せず止める。印の更新・削除は札が自分のものの時だけ |
| 取り消し用の記録 | `operations/<ID>.jsonl` に書けたか | 各ページの保存の直後 | 書けなければ、そのコマンドを「中止」にし、残りのキューも処理せずに終了する（取り消せない編集を増やさない） |
| 着手 | 最新版で節があり、誰も `{{BOTREQ}}` を付けていないこと（2.6） | 編集を始める前（着手の返信と同じ編集） | 見送り |
| 節の確認 | ID で探した節の見出しが変わらず、他の作業者が対応していないこと（2.7） | 編集中2分ごと | 中止（過去ログ化だけなら続ける） |
| 緊急停止ページ | `プロジェクト:カテゴリ関連/キュー/緊急停止` の本文（コメントを除く）が `動作中` | 起動時と1ページ編集するごと | 起動時なら終了、実行中なら中断して次回に回す |
| 編集拒否 | `{{nobots}}` / `{{bots\|deny=…}}`（ログイン中の利用者名で判定） | 各ページの編集前 | そのページを「編集できなかった」に記録 |
| Bot フラグ | API の `assert=bot` | すべてのリクエスト | API エラーで終了 |
| 編集競合 | 取得した版の `basetimestamp` | 保存時 | 最新版を取り直して最大2回やり直す |
| サーバー負荷 | `maxlag=5`（mwn 既定） | すべてのリクエスト | 待って再試行 |
| 編集間隔 | editThrottle（`priority: 'low'`） | 保存時 | 5秒以上空ける。通常優先度のジョブに譲る |

## 8. 記録と取り消し

保存先は実行ファイルと同じディレクトリの `data/category-queue/`（Toolforge では `~/bot/data/category-queue/`）です。

| ファイル | 内容 | 書き込む時点 |
| --- | --- | --- |
| `commands/<ID>.json` | コマンドの概要: `heading` `state` `status` `message` `startedAt` `finishedAt` `resumedAt`（再開した時刻）`started`（着手の返信をしたか） `request`（2.5）`command` `discussionLink` `total` `counts` `notes` `reply`（返信文・投稿したか・できなかった理由）`log`（実行ログ） | 節の処理を始めたとき・依頼者やコマンドが分かったとき・各ページを処理したとき・終わったとき |
| `commands/<ID>.pages.jsonl` | 1行1ページの結果: `at` `title` `result` `revid` `oldrevid` `warnings` `message` | 各ページを処理した直後 |
| `history.jsonl` | 1行1コマンド: 終わった節の概要（`commands/<ID>.json` から実行ログを除いたもの） | コマンドが初めて終わったとき（緊急停止で中断したものは再開して終わったときに書く。返信の再送では書かない） |
| `operations/<ID>.jsonl` | 1行1編集: `title` `pageid` `oldrevid` `newrevid` `timestamp` | 各ページの保存が成功した直後（書けなければ実行を止める。7章） |
| `status.json` | 実行状況（9章） | 随時 |
| `dry-run/<ID>/<ページ名>.before.wiki` / `.after.wiki` | 変更前後の本文 | `--dry-run` で変更があったページごと |

ログ（`logs/public.jsonl` と `private.jsonl`）には、コマンドの開始・終了と件数を記録します。dry-run は非公開ログのみです。コマンドごとの実行ログ（依頼者の警告、ページ単位のエラーなど）は `commands/<ID>.json` の `log` に入り、Web の詳細ページに出ます。

### 8.0 ファイルで記録する理由

データベース（Toolforge の ToolsDB）ではなく JSON / JSONL ファイルにしています。

- 実行は手動で、量は多くても月に数十コマンド・数千ページ程度
- 書き込むのは実行中の1プロセスだけ（`run.lock`）で、Web は読むだけなので、同時書き込みの調停が要らない
- 接続設定・スキーマ・DB の停止といった失敗要因が増えない。バックアップはファイルの写しで足りる
- ページごとの結果は追記だけなので、途中で落ちてもそこまでの記録が残る

定期実行に移ってコマンドが増えたときや、「あるページに対する全操作」「ある利用者の全依頼」のようにコマンドをまたいで検索したくなったときは、ToolsDB に移します。記録はコマンド単位（概要＋ページの結果）に分けてあるので、そのまま表に移せます。

### 8.1 取り消し（--rollback）

1. `operations/<ID>.jsonl` を読みます。無ければエラーで終了します。
2. 新しい編集から順に、MediaWiki の取り消し（`undo=newrevid`、`undoafter=oldrevid`）を行います。編集要約は `Bot: キュー処理 (ID: …) の取り消し` です。
3. 後から他の人が同じ箇所を編集していて取り消せないページは、警告ログに残して飛ばします。
4. 最後に「取り消し終了: 成功件数/全件数」を記録します。

`--dry-run` を付けると、取り消す予定のページを表示するだけです。緊急停止で中断したコマンドは同じ ID で再開するので、1つの ID を取り消せば全体が戻ります。キューページへの返信は取り消しません。

## 9. 実行状況の表示

実行中は `status.json` を書き換え続け、nanonaBot2 Web の `/queue` がそれを読んで表示します（[web.md](web.md)）。

| 項目 | 内容 |
| --- | --- |
| `state` | `running` / `idle` |
| `mode` | `normal` / `dry-run` / `rollback` |
| `startedAt` `updatedAt` `finishedAt` `endReason` | 時刻と終わり方（完了・緊急停止・未処理のキューなし・エラーなど） |
| `sections[]` | 今回の節: `heading` `state`（pending / running / done / stopped）`status`（返信した BOTREQ）`id` `message` |
| `current` | 処理中のコマンド: `heading` `phase` `id` `type` `from` `to` `discussionLink` `request` `total` `done` `edited` `unchanged` `warnings` `errors` `currentTitle` |
| `events[]` | 直近50ページの結果（新しい順）: `at` `title` `result`（edited / unchanged / error）`revid` `warnings` `message` |

ファイルは一時ファイルに書いてから名前を変えるので、読み手が書きかけを読むことはありません。書き出しに失敗しても Bot の処理は止めません。

## 10. コマンドライン

```sh
node dist/category-queue.js                        # 未処理のキューをすべて実行して返信
node dist/category-queue.js --dry-run              # 編集せず変更前後を保存（稼働スイッチ・緊急停止は確認しない）
node dist/category-queue.js --only "Name1"           # 見出しにその文字列を含む節だけ
node dist/category-queue.js --only "Name1" --max-pages 3  # 先頭3ページだけ（返信しない）
node dist/category-queue.js --no-report            # 実行するが返信しない
node dist/category-queue.js --rollback <ID>        # 取り消し
```

返信しない実行では節に `{{BOTREQ}}` が付かないため、次の通常実行でもう一度対象になります（付け替え済みのページは移動元から外れているので二重編集にはなりません）。

### 10.1 試験（test.wikipedia.org）

本番の jawp では記事・カテゴリを実際に編集するので、試験は test.wikipedia.org で行います。`--site test` を付けると、次のように切り替わります。

| 項目 | 本番（`--site ja`、既定） | 試験（`--site test`） |
| --- | --- | --- |
| ウィキ | ja.wikipedia.org | test.wikipedia.org |
| キューページ | プロジェクト:カテゴリ関連/キュー | User:NanonaBot2/カテゴリキュー |
| 緊急停止ページ | プロジェクト:カテゴリ関連/キュー/緊急停止 | User:NanonaBot2/カテゴリキュー/緊急停止 |
| 記録 | `data/category-queue/` | `data/category-queue-test/`（Web の詳細ページは両方を探す） |
| `assert=bot` | 付ける | 付けない（testwiki には Bot フラグが無い） |
| メタの稼働スイッチ | 確かめる | 確かめない |

`--queue-page` と `--stop-page` で、キューページと緊急停止ページを個別に変えられます。jawp の利用者サンドボックスにキューを置いて `--dry-run` で読ませれば、本番の記事を編集せずに見出しの解釈や依頼者の特定を確かめられます。

試験の手順:

```sh
node scripts/queue-test-setup.js --check              # 作るページを表示するだけ
node scripts/queue-test-setup.js                      # testwiki に試験用のページを作る（再実行で初期状態に戻る）
node dist/category-queue.js --site test --dry-run     # 編集せずに確かめる
node dist/category-queue.js --site test               # 実際に着手・編集・返信する
node dist/category-queue.js --site test --rollback <ID>
```

`queue-test-setup.js` が作るもの（名前はすべて「NanonaBot2キュー試験」で始まる）:

| ページ | 確かめること |
| --- | --- |
| カテゴリ Name1・Name2・Name3・Name1 下位 | 移動元・移動先・除去するカテゴリ・下位カテゴリ（Category 名前空間の再配属） |
| 記事1 | ソートキー付きの再配属。Name3 の除去 |
| 記事2 | 空白だけのソートキー（`| `）の引き継ぎ |
| 記事3 | `{{nobots}}`（編集できなかったとして報告） |
| 記事4 | 移動先が既にある（移動元のタグを消すだけ） |
| 記事5 | `{{リダイレクトの所属カテゴリ}}` の引数（検索で見つけて書き換える。索引に載るまで数分かかることがある） |
| 議論 | 編集要約にリンクされる議論場所 |
| キューページ | 再配属・(記事)除去・不受理（コロンなし）・不可能（移動先が無い）・不受理（複製）・異議あり（「Bot:」なし）の6節 |

キューの節は準備したアカウントの署名になるので、依頼者と署名は一致します。署名の偽装を試すには、別のアカウントで、他人の署名を付けた節を足してください。

偽のウィキを使った予行演習で、上の手順どおりの結果になることを確かめています。このとき、キューページ自体が対象になる問題が見つかりました。見出しにコロンなしの `[[Category:…]]` があると、キューページがそのカテゴリに入るためです。キューページと緊急停止ページは、常に対象から外すように直しました。

## 11. QueueBot との差異と未決事項

| 項目 | QueueBot（導入文） | 本タスク |
| --- | --- | --- |
| 実行の契機 | 毎日 7:00 と 15:00（JST） | 運用者の手動実行 |
| 移動先が未作成 | 移動元を移動して作る（導入文では移動機能は停止中） | 「不可能」を返す |
| 移動元が空になった | 即時削除を依頼 | 返信で空になったと伝えるだけ |
| 本文の解析 | Parsoid HTML | wikitext を parse2 で解析（書式を崩さない） |
| 処理済みの判定 | `{{BOTREQ\|完了}}` のみ | `{{BOTREQ}}` があれば引数を問わず |
| 緊急停止時 | `{{BOTREQ\|保留}}` を返す | 返信せず、次回同じ ID で再開する |
| 着手 | 返信しない | `{{BOTREQ\|着手}} (ID: …)` を返信し、以後この ID で節を追跡する |
| `{{bots}}` | 確認なし | 尊重する |
| 変更しなかったページの報告 | なし | 要確認として列挙 |
| 取り消し | DB に記録、別コマンド | JSONL に記録、`--rollback` |
| 実行状況 | なし | Web でリアルタイムに表示 |
| 返信 | エラーのページを列挙 | 1行（件数と Web の詳細ページへのリンク） |
| 依頼者 | 記録しない | 履歴から特定し、署名と照合して記録する |

未決事項:

- [ ] 緊急停止ページを QueueBot と共用するか（現在は `停止中` のため、書き換えるまで編集しない。別ページなら定数 `EMERGENCY_STOP_PAGE` を変える）
- [ ] 「Bot:」だけの対象範囲（導入文は「すべてのページ」、QueueBot の実装は標準と Category のみ。変えるなら `DEFAULT_NAMESPACES`）
- [ ] カテゴリの移動と、空になった移動元への即時削除テンプレートの貼付を実装するか
- [ ] 定期実行への移行（例: 7:00/15:00 JST なら UTC で `0 22,6 * * *`）
- [ ] 提出から実行までの待ち時間（依頼日時を特定済みなので、条件を決めれば実装できる）
- [ ] 依頼者の資格を確かめるか（自動承認済みなど。署名ではなく履歴で特定した依頼者で判定する）
- [ ] 署名と依頼者が一致しないときに実行を止める（保留にする）か。現在は記録と表示のみ
- [ ] 他のテンプレート（カテゴリ名を引数に取るもの、テンプレートのリダイレクト）を対象に加えるか
