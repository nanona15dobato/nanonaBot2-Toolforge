# wikitext パーサー parse2

`src/utils/parse2.js` の `WikitextParser` は、wikitext からテンプレート・リンク・カテゴリ・見出しなどを取り出し、それぞれの元の文字列上の位置を返します。subster（`w-ja-nn4`）とカテゴリキュー（`w-ja-nn5`）が使っています。

2026年10月に処理方式を書き直しました。出力は旧版と互換で、速度は全要素の解析で約2.2倍です（5章）。

## 1. 使い方

```js
const WikitextParser = require('./utils/parse2');
const parser = new WikitextParser();
parser.setSiteInfo(siteinfo);            // 任意。API の meta=siteinfo（namespaces|namespacealiases|interwikimap）
const result = parser.parse(wikitext, { templates: true });
```

`parse` は同期処理で、1つのインスタンスを使い回せます（呼ぶたびに内部状態を初期化します）。

### 1.1 options

| 指定 | 意味 |
| --- | --- |
| 省略・`{}` | すべての種類を解析する |
| `{ templates: true }` | テンプレートだけを解析する。肯定の指定が1つでもあれば、指定したものだけになる |
| `{ templates: ['Foo', 'Template:Bar'] }` | 指定した名前のテンプレート（と subst）だけを返す。名前空間が無ければ `Template:` を補う |
| `{ '!tables': true }` / `{ tables: false }` | その種類だけを除く |

種類は `templates` `variables` `wikilinks` `extlinks` `tables` `headings` `files` `categories` `references` `lists` です。

### 1.2 名前の正規化（normalizeTitle）

`_` を空白に、連続空白を1つにし、先頭文字（名前空間があればその後の先頭文字も）を大文字にします。名前空間は別名から正式名に直します。

| 入力 | 結果（siteinfo なし） | 結果（jawp の siteinfo あり） |
| --- | --- | --- |
| `template:foo_bar` | `Template:Foo bar` | `Template:Foo bar` |
| `カテゴリ:x` | `Category:X` | `Category:X` |
| `File:a.jpg` / `画像:a.jpg` | `ファイル:A.jpg` | `ファイル:A.jpg` |
| `User:Ex` | `User:Ex` | `利用者:Ex` |

siteinfo を読む前でも、日本語版ウィキペディアのファイル(6)・Template(10)・Category(14) の名前と別名は分かるようにしてあります。siteinfo を読むと、各名前空間の正式名（`canonical`、例: `User`）も別名として登録します。

## 2. 出力

`parse` は次の配列を持つオブジェクトを返します。各配列は文書内の開始位置の順です。位置 `position` はすべて **元の wikitext 上** の `{ start, end }`（end は含まない）で、`original` は `wikitext.slice(start, end)` と同じです。

### templates

| 項目 | 内容 |
| --- | --- |
| `type` | `template` / `substTemplate` / `parser_function`（`{{#if:…}}`）/ `magic_word`（`{{DEFAULTSORT:…}}` など） |
| `name` | `Template:名前`（正規化済み）。パーサー関数は `#if` のように小文字、マジックワードは大文字 |
| `args` | `{ キー: 値 }`。位置引数は `1` `2`…。値は前後の空白を除く。同じキーは後のもので上書き |
| `argsOrdered` | **追加。** 書かれた順の引数の配列（重複も残す）。各要素は下表 |
| `namePosition` | **追加。** テンプレート名（前後の空白を除く）の位置 |
| `position` `original` | 呼び出し全体 |

`argsOrdered` の要素:

| 項目 | 内容 |
| --- | --- |
| `key` | 名前付きならそのキー、位置引数なら `"1"` `"2"`… |
| `value` | 値（前後の空白を除く） |
| `named` | `key=値` の形なら true |
| `position` | `|` の直後から次の `|` または `}}` の直前まで（空白を含む） |
| `keyPosition` | キーの位置（名前付きのみ。位置引数は null） |
| `valuePosition` | 値の位置（前後の空白を除く） |

パーサー関数・マジックワードのコロンの後ろは位置引数 `1` になります。

### wikilinks / categories / files

| 種類 | 項目 |
| --- | --- |
| `wikilinks` | `target`（正規化済み）、`text`（表示文字列。無ければ target の元の表記）、`colon`（**追加。** `[[:…]]` の形なら true） |
| `categories` | `category`（名前空間を除いた名前）、`target`、`sortKey`（前後の空白を除く。空なら null）、`sortKeyRaw`（**追加。** 最初の `|` より後ろをそのまま。`[[Category:X| ]]` なら `" "`。`|` が無ければ null） |
| `files` | `file`、`target`、`options`（`|` で区切った各項目） |

`[[:Category:X]]` `[[:File:X]]` はリンクとして `wikilinks` に入ります（旧版はカテゴリ・ファイルとして扱っていました）。

### その他

| 種類 | 項目 |
| --- | --- |
| `variables` | `{{{名前\|既定値}}}` の `name` と `default`（無ければ null） |
| `extlinks` | `[https://… 表示]` の `url` と `text` |
| `references` | `<ref …>…</ref>` と `<ref … />` の `attributes` と `content`（自己終了・空なら null） |
| `tables` | `{\| … \|}` の `attributes`、`caption`、`rows[].cells[]`（`isHeader` `attributes` `text`） |
| `headings` | `id`（同名は `_2` などを付ける）、`level`、`title`、`parents`、`content`（次の同じかより上の見出しまで）、`position.header` と `position.content` |
| `lists` | 行頭の `* # : ;` の `markers` `level` `content` |
| `warnings` | 現在は常に空（互換のため残す） |

見出し・箇条書きは、テンプレートやリンクなどの中にある行を数えません。

### 補助

`WikitextParser.applyEdits(text, edits)` は、重ならない編集 `{ start, end, replacement }` の配列を後ろから適用した文字列を返します。範囲が重なっていれば例外を投げます。parse2 の位置をそのまま使って本文を書き換えるときに使います。

## 3. 処理方式

1. **保護領域:** `<!-- -->` と `<nowiki>` `<pre>` `<math>` `<syntaxhighlight>` `<source>` `<score>` `<chem>` `<ce>` の範囲を見つけます。コメントの中のタグは対象にしません。以降の走査では、この範囲の文字を `\x00` に置き換えた写しを使います（長さは変えない）。
2. **構造の走査（`buildTree`）:** 記号 `{{{` `{{` `}}}` `}}` `[[` `]]` `[url` `]` `{|` `|}` `<ref …>` `</ref>` を1回だけ左から読み、スタックで入れ子の木を作ります。
3. **要素の解釈:** 子 → 親の順に処理します。親の中の子要素と保護領域は「マスク」（`\x01TMPL_12\x02` のような記号）に置き換えて扱うので、子の中の `|` や `=` で区切りを誤りません。値や位置は元の文字列から位置で切り出します。
4. **見出し・箇条書き:** すべての要素をマスクにした文書を行単位で調べ、マスク済みの位置を元の位置に変換表で戻します。

### 3.1 記号の対応の決まり

| 記号 | 決まり |
| --- | --- |
| `}}` | 最も内側の `{{` を閉じる。間に閉じていない `[[` や外部リンクがあれば、それらは捨てる（ただの文字として扱う） |
| `}}}` | 最も内側が `{{{` なら閉じる。`{{` なら `}}` として閉じ、残りの `}` を読み直す |
| `]]` | 最も内側が外部リンクなら `]` 1つで外部リンクを閉じ、残りを読み直す。それ以外は最も内側の `[[` を閉じる |
| `]` | 最も内側が外部リンクのときだけ閉じる |
| `\|}` | 最も内側が表のときだけ閉じる（`{{foo\|}}` の `\|}` を表の終わりと誤らない） |
| `</ref>` | 最も内側の `<ref>` を閉じる。間の閉じていないリンクは捨てる |
| `<ref … />` | その場で自己終了の ref とする |
| `[http…` | `[` の直後が `http://` `https://` `ftp://` と1文字以上の URL のときだけ外部リンクの始まりとする |

最後まで閉じられなかった記号はただの文字として扱い、その中の要素は外側の要素に属します。

## 4. 旧版との違い

旧版は「中に開き記号を含まない最も内側の構造を正規表現で探し、マスクに置き換える」ことを、変化が無くなるまで繰り返していました。

| 項目 | 旧版 | 新版 |
| --- | --- | --- |
| 走査 | 入れ子の深さぶん文書全体を走査し直す。内側に開き記号があると1文字ずらして探し直す | 1回の走査で木を作る |
| 引数の位置・順序 | 無し。`args` はオブジェクトなので位置引数が先に並ぶ | `argsOrdered`・`namePosition` を追加 |
| `[[:Category:X]]` | カテゴリとして扱う | リンク（`colon: true`） |
| 空白だけのソートキー | 区別できない（null） | `sortKeyRaw` で区別できる |
| 名前空間の正式名（`User:` など） | siteinfo の別名に無いと名前空間として扱わない（`{{User:X}}` が `Template:User:X` になる） | 正式名も別名として扱う（`利用者:X`） |
| siteinfo なしのファイル・カテゴリ | `File:x` のまま（先頭文字以外は正規化しない） | `ファイル:X` `Category:X` |
| `templates` の絞り込みに名前空間なしの名前 | 一致しない | `Template:` を補って一致させる |
| 閉じ忘れ（`{{A\|[[B}}` など） | A を解析できないことがある | A を解析する（3.1） |

上の表以外の出力は旧版と同じです。次の比較で確かめました。

- jawp の153ページ（ランダム記事・大きな記事・テンプレート・議論ページ、計5.3MB）
- subster と同じ `{ templates: true }`：**すべてのページで完全に一致**（名前・引数・位置・原文）
- 全要素：追加した項目と名前空間の正規化を除いて完全に一致

`test/parse2.test.js` は、`test/legacy/parse2-v1.js`（旧版）と `test/fixtures/` に置いた実ページの wikitext（`.txt` / `.wiki`）で同じ比較を行います。実ページはリポジトリに含めないので、比べたいときは API などで取得して置いてください（無ければこのテストは飛ばします）。

## 5. 性能

同じ153ページを旧版・新版で交互に5回ずつ解析した中央値です（手元の Windows、Node.js 24）。

| 対象 | 旧版 | 新版 |
| --- | --- | --- |
| 全要素・153ページ合計 | 2532 ms | 1174 ms |
| 全要素・最大ページ（第二次世界大戦、353KB） | 347 ms | 97 ms |
| `templates` のみ・153ページ合計 | 1117 ms | 455 ms |
| `templates` のみ・最大ページ | 179 ms | 55 ms |

壊れた入力・極端な入力:

| 入力 | 旧版 | 新版 |
| --- | --- | --- |
| `{{a\|` を3000段入れ子 | 39,510 ms | 86 ms |
| 閉じない `[[` ×5000 | 237 ms | 13 ms |
| 閉じない `{{` ×5000 + 本文 | 743 ms | 58 ms |
| コメント内の括弧 ×20000 | 183 ms | 191 ms |

速くなった主な理由:

- 文書全体の走査が1回になった（旧版は入れ子の深さぶん走査し、開き記号を含む候補ごとに1文字ずらして探し直していた）
- マスク済み文字列の位置から元の位置への変換を、毎回の再計算から変換表の二分探索にした
- 値・見出しの本文・箇条書きの内容を、マスクの展開ではなく元の文字列から位置で切り出すようにした
- マスクを、親が必要とするときにだけ作るようにした

## 6. 制限

- MediaWiki のプリプロセッサーとは完全には一致しません。特に `{{{{{1}}}}}` のような括弧の連続、行頭以外の `{|`、テンプレートが展開されてはじめて成り立つ構文は、展開せずに字面で判断します。
- `<includeonly>` `<noinclude>` `<onlyinclude>` は区別せず、中も通常どおり解析します。
- 見出しは行全体が `== … ==` の形のものだけを数えます（`<h2>` は数えない）。
- `<code>` の中は保護領域にしません（MediaWiki でも中の wikitext は解釈されるため）。
